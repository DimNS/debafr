# Dev-стенд

Локальный стенд для прогона пайплайна deploy'а без настоящего приложения и без
системного nginx. Вместо приложения крутится `nginx` из публичного реестра —
цель не проверить само приложение, а прогнать все шаги `debafr` целиком.

```
make dev
```

Сборка идёт в `.dev/debafr`, запуск — **из `.dev/`**, поэтому конфиг, compose-файлы
и `nginx.conf` лежат рядом с бинарником и ни от чего в корне не зависят.

## Версии для install и update

Образ подставляется как `nginx:<введённая версия>`, поэтому вводить нужно **тег
alpine-образа**: он в ~4 раза легче debian-варианта.

| Сценарий                       | Что вводить     | Итоговый образ        |
| ------------------------------ | --------------- | --------------------- |
| Первое развёртывание (Install) | `1.28.1-alpine` | `nginx:1.28.1-alpine` |
| Обновление (Update)            | `1.28.2-alpine` | `nginx:1.28.2-alpine` |

Любая другая alpine-версия тоже подойдёт — версия нигде не зашита.

## Что проверяет стенд

Полный цикл из 6 шагов: `Parse ports` → `Pull image` → `Deploying` →
`Healthcheck` → `Switching strategy` → `Stopping current deploy`, плюс шаг
`VictoriaMetrics`, который пишет `debafr.json` с целью активной стратегии.

`nginx.conf` специально содержит `/ws` на том же порту, что и `/`. Приложение
переключает строки глобальной заменой и должно поменять **оба** location'а разом —
если в выводе шага `Switching strategy` поменялась только одна пара строк, это регресс.

Порты: blue `3001/3002`, green `3011/3012`, внешний nginx слушает `8080`.

`nginx.conf` лежит в репозитории **полностью закомментированным**, и это
обязательное состояние: на install у приложения нет текущей стратегии, оно
только раскомментирует следующую. Если оставить активную строку, в одном
`location` окажется два `proxy_pass` и `nginx -t` упадёт.

## Что означают коды ответа

`/` отдаёт `200` — это дефолтная страница образа `nginx`. `/api` и `/ws`
дают `404`: образ-пустышка не знает таких путей, но `404` приходит **из
контейнера**, значит `proxy_pass` сработал. Непрохождение прокси выглядит
иначе — `502` или таймаут.

## Прямой доступ

```bash
make dev-status                     # что сейчас задеплоено
curl -i http://127.0.0.1:8080/api   # через прокси на активную стратегию
curl -i http://127.0.0.1:8080/ws    # второй location на том же порту
cat .dev/debafr.json                # цель VictoriaMetrics
```

`make dev-up` поднимает compose руками, минуя TUI (версия — в `APP_VERSION`).

## Уборка

```bash
make dev-down   # контейнеры приложения и тестовый nginx
make dev-clean  # плюс образы nginx и debafr.json
```

`debafr` ничего не удаляет за собой: остановленный стек остаётся в docker, и это
нужно — на нём проверяется, что следующий deploy найдёт текущий.

## Файлы

| Файл                                       | Роль                                                                 |
| ------------------------------------------ | -------------------------------------------------------------------- |
| `debafr.toml`                              | конфиг приложения; читается из CWD                                   |
| `compose.blue.yaml` / `compose.green.yaml` | фейковое приложение, два стека в одном compose-проекте `debafr`      |
| `nginx.conf`                               | server-блок; приложение правит только строки `proxy_pass`            |
| `nginx.sh`                                 | подмена `nginx` через `docker exec` в контейнере `debafr_test_nginx` |
